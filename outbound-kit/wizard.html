1

어디에서 실행할까요?

내 컴퓨터에서 바로 쓰는지, 준비된 Linux 서버에서 돌릴지 정합니다.

준비된 Linux 서버에 접속하기

SSH는 내 컴퓨터에서 서버에 안전하게 접속하는 방법입니다. 주소·사용자 이름·포트는 서버를 발급한 클라우드 화면에서 찾습니다. 개인키는 내 컴퓨터에만 두고 .pub 공개키만 서버 화면에 등록합니다.

개인키 내용과 서버 비밀번호는 저장하지 않습니다.새 키를 만들면 .pub 공개키를 클라우드 화면에 등록하고, 서버 신원을 따로 확인한 뒤 접속을 시험합니다. 파일 복사가 성공해도 Hermes 설치나 24시간 실행이 끝난 것은 아닙니다. 서버 자동 발급·방화벽 변경·관리자 설치는 포함하지 않습니다.
2

어떤 모델 연결 경로를 쓸까요?

계정 종류만 기록합니다. 사용 가능 모델과 실제 응답은 CLI/Hermes에서 검증합니다.

구독과 API 권한은 다를 수 있습니다.설정 저장만으로 모델이 준비된 것이 아닙니다. harmless prompt에 실제 응답이 돌아와야 통과입니다.
3

어디에서 대화할까요?

처음에는 Desktop/터미널만 써도 됩니다. 메신저는 준비된 사람만 연결하세요.

Telegram 준비

@BotFather에서 봇을 만들고 토큰은 복사해 두세요. 토큰은 나중에 CLI가 화면에 표시하지 않는 비공개 prompt로만 받습니다. 설치 후 Start → 본인 메시지 → 봇 응답 → 비허용 사용자 거부를 확인합니다.

Discord 준비

Guild/Channel 값은 안내용이며 현재 Hermes 버전에 자동 적용됐다고 간주하지 않습니다. 초대·권한·intent·실제 왕복을 각각 확인합니다.

토큰 안전 규칙봇 토큰을 채팅, 이 HTML, setup.json, 캡처 화면에 붙이지 마세요. 실제 기기의 로컬 CLI prompt에서만 입력합니다.
4

오늘 어떤 일을 끝내고 싶나요?

한 가지 시나리오를 고르면 필요한 질문만 보여드립니다. 공개 신호는 구매 확정이 아니라 검토할 단서입니다.

데이터는 어떻게 시작할까요?

채용 신호의 실시간 모드에서만 소스를 고릅니다. 공개 공고를 소량 조회하며 로그인·차단 우회는 하지 않습니다. 다른 시나리오에 live 수집기가 없으면 연습 데이터 또는 내 파일로 시작합니다.

무엇이 자동이고, 무엇을 직접 확인할까요?

아래 요약은 입력에 따라 갱신됩니다. setup.json 생성은 설치 완료가 아닙니다.

CLI가 이어서 할 수 있는 것설정 schema 검사 → 환경 사전점검 → helper/엔진 상태 확인 → 사용자가 승인한 단계 실행 → 증거 receipt와 재개 지점 기록.
사용자가 반드시 관여할 것브라우저 로그인/OAuth, 토큰·키·비밀번호의 로컬 비공개 입력, SSH host 신뢰, 유료 서비스 비용, 기존 vault 승인, 실제 메시지 왕복과 결과 검토.

설치 계획 파일을 생성합니다

이 버튼은 비밀값 없는 setup.json만 다운로드합니다. 새 PC에 Python/Hermes를 설치하거나 계정에 로그인하지 않습니다.

다음 단계 예시: python3 installer.py plan --config setup.json
Windows 예시: py -3 installer.py plan --config setup.json
실제 명령은 저장소의 installer.py --help와 README를 우선합니다.
