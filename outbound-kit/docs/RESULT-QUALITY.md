# 내 컴퓨터에서 결과 품질 확인하기

먼저 `python3 local_smoke.py`를 실행합니다. Windows에서는 `py -3 local_smoke.py`입니다.
새 테스트 폴더만 만들고 네트워크·모델·기존 Hermes를 사용하지 않습니다. 출력의 `vault` 폴더를
Obsidian에서 열면 네 시나리오의 단계별 결과를 볼 수 있습니다.

이 검사는 **결과 연결과 안전 계약** 검사입니다. coverage는 채워진 근거 필드 비율이며,
문장 품질·구매 확률·실제 타겟 적합도 점수가 아닙니다. 합성 후보와 템플릿 초안은 실제 고객에게
보낼 수 있는 AI 결과로 소개하지 않습니다.

## 실제 AI 결과 평가

전용 테스트 home으로 설치한 뒤 사용자가 공개해도 되는 제품 설명과 고객 조건을 입력합니다.
처음에는 공개 공고 3~5개 또는 합성 파일로 진행하고 `draft_mode=hermes`를 선택합니다.
기존 개인 Hermes의 SOUL·메모리·볼트·키를 복사하지 않습니다. 미공개 고객 정보나 비밀 전략을
외부 모델에 보내지 말고 공급자의 데이터 처리 조건을 먼저 확인합니다.

각 초안을 아래 항목으로 사람이 평가합니다. 0은 불충족, 1은 수정 필요, 2는 충분함입니다.

| 평가 항목 | 확인 질문 |
|---|---|
| 근거 정확성 | 주장에 원문 URL이 있고 공고·기사 내용을 왜곡하지 않았는가? |
| 적합성 | 내 제품과 상대의 확인된 업무 사이에 구체적인 연결이 있는가? |
| 불확실성 | 채용·투자를 구매 의사로 단정하거나 담당자·매출 등을 지어내지 않았는가? |
| 맞춤성 | 회사 이름만 바꾼 일반 문구가 아니라 공개 근거를 적절히 활용했는가? |
| 읽기 쉬움 | 짧고 자연스럽고 과장·기술 용어·불필요한 아첨이 없는가? |
| 다음 행동 | 부담이 낮고 명확한 질문 하나가 있는가? |
| 개인정보 | 사적 내용·비밀값·다른 고객 사례가 들어가지 않았는가? |

총점만으로 통과시키지 않습니다. 근거 정확성·불확실성·개인정보 항목에 0이 있으면 반드시 반려합니다.
사용자가 수정한 최종 문장은 Review에 보존하고, 원문·제품·초안이 바뀌면 다시 검토합니다.
현재 테스트가 이 실제 AI 품질 평가를 대신 수행했다는 주장은 하지 않습니다.

## 테스트봇으로 질문하기

`docs/TEST-BOT.md`에 따라 본인만 접근하는 Telegram 봇을 연결합니다. 먼저 “채용공고로
고객 후보를 찾고 싶어. 무엇부터 정하면 돼?”라고 질문합니다. 목적과 제품·고객 조건을 조금씩 묻고,
모르는 용어를 설명하며, 수집 실패를 0건 또는 샘플 성공으로 바꾸지 않는지 확인합니다.
봇은 초안 확인과 요청 인터페이스입니다. 메시지를 보냈다는 이유만으로 자동 발송을 허가하지 않습니다.
