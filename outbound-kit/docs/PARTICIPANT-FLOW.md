# 참가자 설치 여정

## 공통 흐름과 완료 조건

| 단계 | 참가자 행동 | 통과 증거 | 실패 시 |
|---|---|---|---|
| 준비 | 모델 계정 1개, 선택 채널 봇/본인 ID 준비 | 로그인 가능, ID 확보 | 로컬·샘플 실습으로 시작 |
| 설정 | wizard.html에서 실행 장소·채널·제안 입력 | setup.json 검사 통과 | 오류 필드 수정 |
| 엔진 | AI 설치 스킬로 OS·Python·Hermes 확인 | hermes 실행 및 버전 확인 | 공식 설치 절차·담당자 지원 |
| 팩 | 전용 home에 설치 | outbound 스킬 파일 확인 | 기존 변경 보존·별도 home |
| 모델 | 개인 화면에서 로그인 또는 API 키 입력 | 실제 질문에 응답 | 권한/한도 확인·샘플 계속 |
| 채널 | 선택한 봇 토큰 비공개 입력 | API 검사와 본인 ID 제한 | 토큰 교체·재시도 |
| 대화 | 각 봇에 본인이 테스트 메시지 | 각각 응답, 허용 안 된 계정 거부 | intent/초대/권한/allowlist 확인 |
| 결과 | 샘플 후 개인 조건으로 조사 요청 | 출처와 초안 저장 | 데이터·도구 실패 구분 |
| 운영 | 재시작·중지 실습 | 다시 응답·중지 후 비응답 | 로그 확인 |

## 8개 옵션 경로

| 실행 장소 | 채널 | 필요한 입력 | 시작 | 추가 합격 기준 |
|---|---|---|---|---|
| Desktop | 없음 | 모델 계정 | chat | 로컬 대화 |
| Desktop | Telegram | 모델, TG 토큰/본인 ID | gateway | TG 왕복 |
| Desktop | Discord | 모델, DC 토큰/본인 ID | gateway | DC 왕복·intent |
| Desktop | 둘 다 | 위 두 채널 입력 | gateway | 두 채널 독립 왕복 |
| Server | 없음 | SSH, 모델 계정 | SSH chat | SSH 재접속 |
| Server | Telegram | SSH + TG 입력 | gateway | 서비스 재시작/재부팅 |
| Server | Discord | SSH + DC 입력 | gateway | 서비스 재시작/재부팅 |
| Server | 둘 다 | SSH + 양쪽 입력 | gateway | 두 채널 + 서비스 복구 |

서버의 없음 옵션은 SSH 로컬 대화 모드이며 알림 수신 채널이 없습니다.
데스크톱은 절전·종료 중 자동화가 멈춥니다. 둘 다 선택해도 모델은 하나로 시작합니다.

## 지원자가 기록할 것

OS/아키텍처, 실행 장소, 채널, 엔진 버전, 마지막 통과 단계, 오류 코드,
모델 실제 응답 여부, 각 채널 왕복 여부, 결과 위치, 중지 확인.
토큰·키·대화 원문은 지원 기록에 넣지 않습니다.

## 재시도

같은 설정/팩 설치와 동일 샘플 실행은 반복 가능합니다. 모델 설정이 .env에 있어도
채널 키를 추가할 수 있습니다. 이미 선택 채널 키가 있으면 기존 값을 보존하고
upstream gateway setup으로 점검합니다. 모델 연결 실패 시 채널 설치로 진행하지 않습니다.
두 번째 봇 검사 실패 시 새 채널 키를 모두 저장하지 않고 다시 입력받습니다.

## 실제 기기 리허설 카드 (미실행)

Mac Apple Silicon/Intel, Windows 11, Linux 서버 각각 새 사용자로 ZIP 해제부터 실행.
Python/Hermes 없음, 기존 설치, 공백·한글 경로, 다운로드 차단, 로그인 취소,
잘못된 토큰, Discord intent off, Telegram Start 미실행, 허용 안 된 사용자,
두 채널 중 하나 장애, 재실행, 절전, 재부팅을 점검합니다.
자동 테스트의 모의 API 성공을 이 카드의 실채널 통과로 옮겨 적지 않습니다.
