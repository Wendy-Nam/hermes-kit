# hermes-kit 수강생 배포 준비도

2026-09-27 코드·CI·배포 접근성 재검토. 목적: 강사의 운영 서버를 수작업으로 복제하지 않고, 수강생이 지원 가능한 동일한 설치 결과를 얻도록 한다.

## 판정

**설치 기반은 있으나, 지금 그대로 초보 수강생에게 배포할 완성본은 아니다.** 특히 강사 서버의 OMH·OmniRoute·자아 기능이 학생 이미지에 이미 들어 있다는 전제로 수업을 설계하면 안 된다.

이번 검증: 로컬 단위 테스트 87개(설정 병합 3 + kit-setup 84) 통과. 최근 GitHub Actions 성공 확인. CI는 이미지 빌드·패치·비밀 스캔·더미 토큰 첫 부팅/재부팅을 검사한다. 학생의 실제 Discord 로그인, 모델 답변, 동기화, 복구까지 검증하지는 않는다. 신규 VPS 설치 리허설은 이번에 수행하지 않았다.

## 구현과 공백

| 기능 | 현 상태 | 수강생에게 약속 가능한 범위 |
|---|---|---|
| 고정 베이스 이미지·rtk·설정·볼트 시드 | 구현 및 CI 성공 | 설치 기반으로 활용 가능 |
| Discord 키 입력·검증·저장 | 구현 및 로직 테스트 | 실제 최초 로그인부터 E2E 필요 |
| 주인 승인·doctor | 구현 | doctor는 실제 모델 응답·팩 완전성·동기화·백업을 보증하지 않음 |
| 직무별 키트 | 목록/메타데이터 존재 | 선택→설치 실행 연결은 미구현 |
| Syncthing | compose와 볼륨 존재 | PC 페어링/폴더 공유 UI 미구현 |
| OMH·자아·turn-router | 이미지에 미포함 | 운영 서버와 같은 기능이라고 안내 불가 |
| OmniRoute | 별도 compose 존재 | 주석에서 약속한 /setup 자동 연결 경로 미구현 |
| 백업·업데이트·연결 해제 | 함수/테스트 존재 | 실제 사용자 흐름·예약 실행 연결 미완성 |
| 배포 이미지 | 학생용 태그 명시됨 | 이번 익명 GHCR 조회 403; 익명 pull 가능 확인 필요 |
| 비공개 팩 | 다운로드 코드 존재 | 저장소 조회 404(부재/현재 권한 부족 구분 불가); 배포 접근성 확인 필요 |

## 배포 전에 해결할 실제 문제

### P0 — 첫 대화와 설치 성공 판정

- `/setup`은 Gemini 키만 있으면 완료를 허용한다. `required_one_of: sub`는 검증하지 않는다. 계획된 ChatGPT OAuth와 메인 모델 선택/추론 확인은 연결돼 있지 않다.
- 봇 초대/권한 설정 코드가 /setup 내부에 있어, 최초로 /setup에 도달하는 외부 절차가 별도로 필요하다.
- HomeView는 팩 키 버튼만 표시한다. `kits.json`의 skills_dir/installer를 실행하지 않는다.
- ‘준비 끝’은 재시작 성공 메시지에 가깝다. 실제 대화 한 번과 선택 기능 검증을 통과해야 완료로 표시하도록 바꾼다.
- 이미지 익명 pull과 코드 유효성 확인 후에 학생용 설치문을 배포한다. 현재 저장소의 태그 목록은 비어 있고, CI의 publish는 태그에서만 실행된다. 패키지 미발행/비공개 등 정확한 원인은 따로 확인해야 한다.

### P0 — 실패 복구

- 첫 부팅 공개 스킬/팩 다운로드 실패 뒤에도 `.kit-version`을 기록한다. 다음 부팅은 같은 버전이면 즉시 종료해, 네트워크가 복구되거나 코드를 나중에 넣어도 재시도하지 않는다.
- 코어 시드 버전과 선택 구성요소 설치 상태를 분리한다. /setup 재시도에서 실패한 구성요소만 재설치하고 사용자 수정은 보존한다.
- 팩의 필수 manifest/파일이 없어도 성공으로 반환하는 경우를 막는다. 이미지와 팩의 검증 버전 및 해시를 묶는다.

### P0 — 실제로 잘못 연결된 기능

- Webshare 팩은 프록시 username/password를 받지만 validator는 각 입력을 API token처럼 취급한다. 올바른 입력 계약으로 통일해야 한다.
- 백업 목적지가 백업 대상 vaults 아래에 있어 과거 tar.gz를 다음 백업에 다시 넣는다. 임시 데이터로 이 동작을 재현했다. 현재 작성 중 자기 파일은 tarfile이 제외하므로 ‘현재 파일 무한 자기복사’로 과장하지 않는다.
- 백업의 실행 실패도 종료코드 0으로 끝난다. 같은 날짜 정상 재실행과 실제 실패를 구분해야 한다.
- backup/updates install_cron은 실제 설치 흐름에서 호출되지 않는다. 직접 쓰는 schedule/command 구조는 설치 Hermes의 정식 cron API 계약에 맞춰 바꿔야 한다. updates.py는 실행 진입점도 없다.

### P1 — 기능의 끝까지 연결

- Syncthing PC 페어링, 폴더 공유, 양방향 파일 도착 확인.
- 백업을 만든 뒤 새 빈 환경에 복원해 노트·설정·스케줄 재현 확인. 키는 /setup에서 재입력.
- 해제/재연결 UI, 모델·OAuth 만료 조치, 마스킹된 강사용 지원 기록.
- image/pack 버전 표시, 업데이트 전 백업, 구버전 복귀 절차.
- Dockerfile의 rtk는 x86_64 고정이다. 초기 지원 환경을 amd64로 명시하거나 arm64 산출물을 별도로 지원한다.

## 제품 범위 제안

### 1. 기본 키트: 첫날 성공 보장

Discord 한국어 비서 + 명시적인 기본 모델 연결 + 영상 요약/노트 저장/선택한 직무 스킬 1개 + 진단·백업·복원. 사용하지 않는 선택 기능은 설정을 요구하지 않는다. 학생의 첫 산출물까지 지원 범위를 고정한다.

### 2. OMH 심화팩: 강사의 작업 방식 제공

사용자가 원하는 차별점인 작업별 모델 추천·위임·보정·검수를 묶어 제공한다. 운영에서 준비→보정→실행 연결을 검증한 버전을 사용한다. OMH만 설치하고 효과를 기대하지 않는다. category/model 매핑, 허용 제공자, 실제 실행 기록, 예산 기본값, 최소 회귀 시험을 포함한다.

OMH는 반드시 OmniRoute와 동시에 켜야 하는 것으로 묶지 않는다. 지원하는 직접 제공자 경로를 먼저 검증할 수 있다. 다중 제공자 관리가 필요한 학생에게 OmniRoute를 추가한다.

### 3. 자아·자율성 선택팩

개인화/기억/피드백 학습/자율 행동은 단계별 opt-in으로 제공한다. 강사의 개인 SOUL, 관계 설정, 사용자 ID, 개인 크론, 생활 데이터, 계정·쿠키를 복제하지 않는다. 수강생이 정하는 정체성과 빈도/예산/중지 기능을 제공한다. 현재 이 팩의 제품화는 미구현이다.

## 강사가 할 일과 개발에서 할 일

강사:

1. 첫 수업 종료 시 학생이 성공해야 하는 결과를 3개로 고정한다. 예: Discord 질문 응답, 영상 링크 요약 저장, 다음 날 노트 재확인.
2. 기본 모델 연결 경로 하나와 초기 지원 OS/서버 조건 하나를 정한다. 여러 구독 선택지를 첫 화면에 모두 노출하지 않는다.
3. 실제 초보자 2~3명에게 안내서만 주고 설치를 관찰한다. 강사가 대신 터미널을 고친 지점을 실패로 기록한다.
4. 수업에서 약속할 기능은 이 리허설을 통과한 범위로 제한한다.

개발:

1. 위 P0를 먼저 고치고 기본 사용 경로 E2E를 완성한다.
2. 배포물/팩 버전을 고정하고 익명 이미지 접근, 정상/만료 코드, 네트워크 장애 복구를 검사한다.
3. 설치 안내서 한 장 + 강사용 지원/복구 안내서 한 장을 만든다.
4. 그 이후 OMH 심화팩, 마지막으로 자아 선택팩을 제품화한다.

## 출시 통과 기준

- 새 계정/빈 볼륨/강사 개인 파일 없이 시작 가능.
- 문서만 따라 봇 초대→키/로그인→첫 응답→선택 스킬 산출물까지 완료.
- 잘못된 키·만료 코드·일시 네트워크 실패에서 수정 후 이어가기 가능.
- 재시작/이미지 교체 후 학생 노트·설정 유지.
- 설치된 기능과 미설치/실패 기능을 화면에서 구분.
- 백업에서 빈 새 환경으로 복원 성공.
- 강사에게 전달하는 진단에 키/개인 대화 원문이 없음.
- 약속한 설치 시간과 지원 환경은 리허설 실측으로 결정. 현재 ‘20분’은 목표이지 이번 검토로 입증한 수치가 아니다.

지금은 기능 개수보다 이 통과 기준을 충족하는 것이 우선이다. 위 문제들은 이번 평가에서 확인했으며 아직 수정하지 않았다. 운영 자아 플러그인 수정과 학생 이미지 반영은 별개다.
