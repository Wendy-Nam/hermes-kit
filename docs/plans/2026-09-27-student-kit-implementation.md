# 학생용 kit 구현 및 검증 — 2026-09-27

이 문서는 같은 날짜의 readiness 보고서 이후 구현 상태를 기록한다.

## 제공 범위

- 학생용 자아 플러그인, 개인 운영 프롬프트·기억, 셀카 선톡은 포함하지 않는다.
- 일반 선톡은 기본 비활성이다. 학생이 채널·시각·주제를 지정하면 하루 한 번 텍스트를 생성한다. 해제 기능과 실행 전후 해제 상태 확인을 제공한다.
- `/setup`: 서비스 연결, 메인·보조 모델 선택 및 실제 응답 검증, ChatGPT 기기 로그인, 직무별 스킬 설치, 설치 재시도, OMH·OmniRoute 선택 연결, 동기화·대화 가져오기·백업·연결 해제.
- OMH는 고정된 upstream 소스와 해시를 검증하여 설치한다. memory off를 적용한다. 개인 운영 서버의 커스텀 패치는 배포하지 않는다. 작업별 모델 최적화는 학생의 모델 구성에 맞춰 추가 설계할 여지가 있다.
- OmniRoute는 기본 `next` 이미지(별도 태그·digest 고정 가능)와 연결별 콤보·제한 키를 사용한다. 실제 도구 왕복 검증을 통과한 뒤 보조 모델에 적용하며 메인 모델을 유지한다.
- 다섯 직무 스킬은 이미지에 기본 제공한다. 비공개 추가팩은 별도 접근키·고정 커밋·manifest가 필요하다.
- 백업·업데이트 알림을 실제 Hermes 스케줄러에 등록한다. 복원은 빈 폴더로만 수행하며 복원한 예약 작업은 정지한다.

## 검수에서 추가로 고친 문제

- 설치 성공 표시 뒤 누락된 구성요소를 복구하지 못하던 경로를 재시도 가능하게 변경.
- 모델 검증 실패 시 기존 설정을 유지하고, 적용 전에 메인·보조 모델 모두 확인.
- 설정과 환경파일을 잠금·원자적 저장으로 보호. OMH 설치 실패 복구 중 동시 사용자 변경 유실 방지.
- Composio consumer key와 Connect MCP 프로토콜, Syncthing의 장치·폴더 등록, 대화 ZIP의 경로·크기·분기 검증.
- 백업에 인증정보가 포함되는 경로, 자기 자신을 다시 백업하는 경로, 연결 해제 스냅샷 실패 처리 보완.
- 모델 점검·선톡 생성에 도구와 개인 문맥이 실리지 않도록 격리. OAuth 갱신은 실제 홈에 저장해 회전 토큰 유실 방지.
- 학생 이미지의 개인 정보 검사에 걸린 테스트용 운영 ID를 합성 값으로 교체. 운영 기록은 빌드 문맥에서도 제외.

## 검증과 남은 배포 단계

로컬 단위 테스트 및 실제 고정 Hermes 런타임의 테스트를 수행했다. 실제 런타임에서는 플러그인 테스트 153개가 통과했다. 저장소 YAML 병합 테스트 3개도 통과했다. 최종 이미지의 개인정보 검사, 음성 패치 검증, 첫 부팅·재부팅 멱등성 검사도 모두 통과했다.

외부 통신 없는 컨테이너에서 실제 Hermes 클라이언트와 가짜 모델 서버를 사용해 메인·보조 모델, 선톡 생성·해제, 도구 및 개인 문맥 미포함을 검증했다. 별도 격리 환경에서 OMH 설치·등록과 OmniRoute의 실제 API 구성 및 중복 없는 재시도를 검증했다. 실제 Discord 발송은 하지 않았다.

학생용 이미지 `hermes-kit:student-k2`는 VPS의 격리된 테스트 환경에서 빌드했다. 운영 에이전트에 학생 설정을 적용하거나 공개 레지스트리에 배포하지 않았다. 새 이미지의 공개 릴리스, 실제 학생 계정 OAuth·PC 동기화·Discord 수신 리허설은 배포 전 남아 있다. OMH의 실제 장기 위임 실행과 유료 공급자의 실제 응답은 이 검증으로 보장하지 않는다.


## 최종 공통 패치 검증

이미지 자동 분석에 사용자 질문 전달, 병렬 2개·전체 30초 제한, 실패 시 같은 턴 자동 재시도 억제를 추가했다. `/setup` 이미지 연결은 합성 이미지 판독과 도구 왕복 검증 후 적용하며, 기존 사용자 이미지 설정을 보존한다. 같은 화면의 `disconnect`는 키트 소유 설정만 복원한다. 공유 Vision Bridge 비활성화는 명시적 선택이며 해제 시 다른 앱을 위해 임의로 재활성화하지 않는다.

Cline 무료 후보 조회는 최신 공개 가격을 검사한다. 입력·출력 및 제공된 추가 가격이 모두 0이어야 후보이며 캐시 가격 미표시는 별도로 알린다. 조회는 무료 호출 성공이나 향후 무료 유지의 보장이 아니다. 운영용 풀 관리 도구는 계획·탐색·적용 시 가격을 재검사하지만, 학생 UI에 모든 요청의 실시간 가격 차단 기능이 구현된 것은 아니다.

최종 `hermes-kit:student-k2` 이미지에서 플러그인 테스트 **187개**, 저장소 병합·비전 패치 테스트 **9개**가 통과했다. 네트워크 차단 실행 점검, 개인정보 검사, 첫 부팅 및 재부팅 멱등성 검사가 통과했다. 공개 이미지 게시와 신규 수강생 계정의 설치 리허설은 아직 남아 있다.


## 공개 배포 리허설에서 확인한 보완

k2 태그의 GitHub Actions 전체 검증과 GHCR 업로드가 성공했다. 패키지를 public으로 설정한 뒤 빈 Docker 인증 디렉터리에서 `ghcr.io/wendy-nam/hermes-kit:0.21.2-k2`를 다운로드하고 새 볼륨의 첫 부팅·재부팅이 통과했다. 소스 저장소는 private 상태를 유지한다.

리허설에서 추가 문제를 찾아 k3에 반영했다. 비공개 GitHub Releases 조회는 학생에게 404가 되므로 업데이트 알림을 공개 GHCR 익명 조회로 교체했다. `latest`와 digest가 같은 버전만 안내하며 후보 수와 네트워크 조회를 제한한다. Syncthing의 존재하지 않는 `v1.27.10` 태그를 실제 `1.27.10` 및 검증된 digest로 고정했다. CI에 Compose 버전 일치와 동반 이미지 존재 확인도 추가했다.

신규 업데이트 조회 테스트 11개가 추가되어 플러그인 테스트는 198개다. 실제 공개 k2의 최신 버전을 인증정보 없이 조회하는 데 성공했다. 신규 학생의 Discord/OAuth 로그인과 물리 PC 연결은 별도 리허설 범위다.

새 Syncthing config 볼륨의 root 소유권 때문에 인증서 생성에 실패하는 문제도 확인했다. 동일한 고정 이미지의 일회성 초기화 서비스가 config·vaults 볼륨의 최상위 소유자만 uid/gid 10000으로 맞추고 config 접근 권한 700을 적용한 뒤 Hermes와 Syncthing이 시작하도록 구성했다. 기존 하위 파일의 소유권은 재귀적으로 바꾸지 않는다.

격리된 두 Syncthing 인스턴스와 공개 k2 이미지의 실제 `pair_device`로 양방향 동기화도 검증했다. 서버 업무 볼트→모의 PC, 모의 PC 개인 볼트→서버의 한국어 합성 파일 내용과 uid 10000이 일치했다. 같은 장치 재등록도 성공했다. 공개 포트와 실제 사용자 PC 없이 실행했고 생성한 시험 컨테이너·볼륨·네트워크는 정리했다. 실제 학생 PC의 방화벽·네트워크 조건은 이 시험과 구분한다.
