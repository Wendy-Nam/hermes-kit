# hermes-kit 0.21.2-k13

4GB VPS에서도 안전하게 돌고, OmniRoute를 강사 서버처럼 대화까지 쓸 수 있게 한 릴리스입니다.

- **스왑 자동 설정.** 기본 Compose에 `swap-init`이 추가됐습니다. 메모리가 7GB 미만이고 스왑이 없고 디스크 여유가
  6GB 이상일 때만 2GB 스왑 파일을 한 번 만듭니다. 메모리가 몰려도 봇이 강제 종료되지 않고 잠깐 느려집니다.
  호스트에 스왑을 켜야 해서 privileged로 한 번 실행되고 끝나며(종료 0이 정상), 실패해도 봇 시작을 막지 않습니다.
- **역할 작업 동시 실행 제한.** 7GB 미만 VPS에서는 kanban 역할 작업을 한 번에 하나만 띄웁니다(작업 하나가 별도
  Hermes 프로세스로 0.3~0.5GB). 8GB 이상은 3개.
- **OmniRoute 메모리 상한.** 심화 Compose의 OmniRoute는 2GB(+스왑 1GB)로 제한됩니다. 넘으면 OmniRoute만 재시작됩니다.
- **OmniRoute 모드.** `/setup → 고급 설정 → OmniRoute 연결 → OmniRoute 모드`. OmniRoute 대시보드에서 직접 연결한
  계정(구독·무료·API 키)의 모델 ID를 대화용·강한 작업용으로 최대 5개씩 입력하면, 키트가 하나씩 도구 호출 시험을 하고
  통과한 것만으로 콤보 두 개를 만듭니다. 대화는 대화용 콤보, 위임·OMH·역할 프로필은 강한 작업용 콤보로 갑니다.
  **지금 쓰던 직접 연결 모델이 대체 경로로 남아서, OmniRoute가 멈춰도 봇은 계속 답합니다.** 웹 스크래핑 제공자는
  쓰지 않습니다. 대화 모델이 OmniRoute를 거치면 Hermes RTK는 자동으로 꺼집니다(OmniRoute가 압축). **모드 끄기**로 되돌립니다.
- **역할 프로필은 위임 모델을 씁니다.** 보조 모델(또는 OmniRoute 모드의 강한 작업 콤보)이 있으면 그 모델로, 없으면
  대화 모델로 돕니다.

검증: 새 볼륨 설치 전체와 실제 OmniRoute 컨테이너로 모드 연결, OmniRoute를 거친 실제 대화, OmniRoute를 멈춘 뒤
직접 연결로 이어지는 대화, 모드 끄기까지 CI에서 매번 돌립니다. 스왑은 일회용 CI 서버에서 실제로 켜고 끕니다.
확인하지 못한 것: Hostinger VPS에서 privileged 실행 허용 여부(허용하지 않으면 스왑만 건너뜀), 실제 구독 계정 모델.

기존 학생: Compose 전체를 새 파일로 바꿔 재배포합니다(스왑 서비스가 추가됨). 데이터 볼륨은 유지됩니다.
