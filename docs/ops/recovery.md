# 키트 백업과 복구

주간 백업은 월요일 04:00에 LLM 없이 실행되며 `/opt/data/vaults/personal/_backup`에 날짜별 압축 파일을 보관합니다. 최근 4개만 유지합니다. 같은 날 재실행은 기존 파일을 덮어쓰지 않습니다. 백업 실패는 크론 실패로 보고되며, 실패한 파일은 정식 백업 이름으로 남지 않습니다.

백업 대상은 메모, SOUL, 설정, 크론 선언, 프로필, 볼트입니다. 대화 세션 DB, 로그인 세션, `.env` 계열과 자격증명 파일, 예전 백업은 제외합니다. YAML 설정과 크론 JSON의 키·토큰·비밀번호 필드 원문도 제외합니다. 노트 본문에 사용자가 직접 쓴 비밀정보까지 자동 제거하는 기능은 아닙니다. 설정의 `${ENV_NAME}` 참조는 유지하고 직접 입력했던 인증값은 재입력 표시로 바뀝니다.

백업이 같은 VPS에만 있으면 서버 삭제 시 함께 없어집니다. Syncthing 연결을 실제로 완료하거나 백업 파일을 PC에 내려받아 서버 밖 사본을 확보하세요. 백업 전용 기능은 Syncthing 연결을 자동 생성하지 않습니다.

## 강사용 복구 절차

복구는 자동으로 실행되지 않습니다. 작동 중인 서버에 덮어쓰지 않고 **존재하지 않는 새 디렉터리**에 먼저 풀어 검수합니다.

```sh
/opt/hermes/.venv/bin/python /opt/data/plugins/kit-setup/restore.py \
  /path/to/2026-09-27.tar.gz --target /tmp/kit-restored
```

경로 탈출, 심볼릭 링크, 자격증명 파일, 예상하지 않은 최상위 경로, 중복 경로가 들어 있는 압축 파일은 거부합니다. 2GiB 또는 10만 파일을 넘으면 수동 검수가 필요합니다. 오류가 나면 결과 디렉터리를 게시하지 않습니다. 기존 대상 디렉터리가 있으면 덮어쓰지 않습니다.

1. 복구 결과에서 메모·SOUL·볼트 파일을 확인합니다. 모든 복구 크론은 `enabled=false`로 중지됩니다.
2. 새 키트 인스턴스를 준비하고 게이트웨이를 멈춘 상태에서 복구 결과를 데이터 볼륨에 옮깁니다. 기존 인스턴스는 보존하세요. `vaults`는 별도 볼륨이므로 그 볼륨에도 복원해야 합니다. 새 이미지가 설치한 `plugins/kit-setup`은 유지합니다.
3. 파일 소유자를 새 컨테이너의 `hermes` 사용자와 맞춥니다. 복구 디렉터리는 접근 권한 700, 파일은 600입니다.
4. Discord 봇 토큰·모델 로그인·API 키는 다시 연결합니다. `/setup`과 `/doctor`를 실행하고 실제 대화를 한 번 확인합니다. `[REENTER VIA SETUP]` 표시가 남은 설정은 해당 인증을 재설정합니다.
5. 크론 목록을 검수하고 채널·스킬·스크립트 경로가 새 인스턴스에서 유효한 작업만 공식 Hermes 크론 명령으로 다시 활성화합니다. 복구 직후 외부 메시지가 자동 발송되지 않도록 전체 자동 재개는 하지 않습니다.
6. 새 백업을 만들고 다른 새 디렉터리에 다시 복구하여 노트 한 개 이상을 대조합니다. 검증이 끝날 때까지 이전 서버와 백업을 지우지 마세요.

## 유지보수 작업 등록 계약

`maintenance.install_all(data_dir)`는 두 작업의 `(ok, message)` 목록을 반환합니다. `ok=false`는 메시지로 **이미 등록**과 **등록 실패**를 구별합니다. Hermes 공식 `create_job_with_scheduler_registration` API를 사용하며, 정식 `script`, `no_agent`, 정규화된 스케줄과 다음 실행 시각을 저장합니다. 등록 API가 없거나 실패하면 raw `jobs.json` 쓰기로 우회하지 않습니다. 운영자가 중지한 작업은 자동으로 다시 활성화하지 않습니다.

업데이트 검사는 `/opt/kit/RELEASE_VERSION`(예: `0.21.2-k1`)을 사용하며, 대체 경로는 `/opt/data/.kit-release-version`입니다. 신규 릴리스가 있을 때만 메시지를 출력하고 조회 실패는 오류로 남깁니다. 자동 업데이트는 하지 않습니다.
