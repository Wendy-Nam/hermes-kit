# k15 — 점검에서 나온 실제 결함 수정

`0.21.2-k15`. k14까지 설치 자체는 정상 동작했지만, 전체 리뷰에서 학생이 실제로 막히는 결함이 6건 나왔습니다.

## 고친 것

1. **OmniRoute 비밀번호를 비우면 기동을 멈춥니다.** Compose가 조용히 빈 값으로 시작해서 "비밀번호가 없는 대시보드"가 뜨고, 학생이 입력한 비밀번호가 계속 실패했습니다. 이제 기동 전에 명확히 거부합니다.
2. **4GB 보호가 제때 준비됩니다.** Hermes가 스왑 파일을 만드는 중에도 동시에 올라가던 것을 순서로 기다리게 했습니다. 메모리가 가장 부족한 첫 부팅 순간에 보호가 없습니다.
3. **스왑 실패 로그가 사실과 달랐습니다.** 새로 만든 파일을 지웠는데도 "파일은 남기지 않음"이라고 출력했습니다. 기존 파일을 지우지 않은 경우와 구분해 이제 정확히 말합니다.
4. **API 키 입력 경로에서 저장 실패를 숨기고 있었습니다.** 설정 파일 쓰기가 실패해도 성공한 것처럼 보였습니다.
5. **"마지막 버튼" 안내가 틀렸습니다.** 옵시디언 노트 동기화 버튼은 마지막이 아니라 `고급 설정`이 마지막입니다. 버튼 이름을 그대로 적었습니다.
6. **OmniRoute 문서에 마지막 단계가 없었습니다.** 3단계(재시작)를 빠뜨리면 "연결했는데 변화가 없다"가 됩니다. 이제 README와 강사용 안내에 3단계, 대시보드 링크 닫기 버튼, 그리고 **기본 프로젝트를 먼저 배포할 것 / `down`으로 지우면 안 될 것**을 넣었습니다.

## 학생 안내

- k14 이하를 받은 학생: k14도 동작하지만 위 1·4·6번이 있습니다. 시간 되면 k15로 올려 주세요.
- OmniRoute를 쓰는 학생은 특히 1번이 중요합니다. 비밀번호를 정하지 않고 배포한 경우 대시보드가 열려 있습니다. **반드시 비밀번호를 정하고 다시 배포하세요.**

## 확인한 것

- 단위 테스트 243개 통과.
- Compose 문법 검사 통과, 비밀번호 빈 값 거부 동작을 실제 `docker compose config`로 확인.
- 스왑 분기 로그를 두 경우(새 파일 / 기존 파일) 각각 시뮬레이션해 확인.
