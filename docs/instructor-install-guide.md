# 설치 도우미 안내 (강사용)

수강생 한 명을 설치부터 첫 대화까지 데려가는 절차입니다. 학생용 요약은 [README](../README.md)의
"수강생 설치 순서"이고, 이 문서는 그 옆에서 강사가 무엇을 확인하고 어디서 막히는지를 다룹니다.

원칙 세 가지:

- **키는 학생 손으로만 입력합니다.** 봇 토큰·API 키·`.env`·대화 ZIP 원본은 받지도, 화면공유로 보지도 않습니다.
  키를 입력하는 순간에는 화면공유를 잠시 멈추게 합니다. 강사가 보는 것은 `/doctor`의 **강사에게 보내기용 복사본**(키 모양 문자열·토큰·ID·이메일 마스킹됨)과 컨테이너 로그입니다.
- **완료는 "키를 넣었다"가 아니라 "응답을 확인했다"입니다.** `/setup`의 연결 확인이 실제 모델 응답을 받아야 적용이 됩니다.
- **한 번에 한 단계.** 각 단계의 확인 지점을 통과한 뒤 다음으로 넘어갑니다.

## 1. 사전 안내 (수업 전날 보낼 것)

| 준비물 | 내용 |
|---|---|
| VPS | Docker를 쓸 수 있는 VPS. Hermes만 쓰면 RAM 4GB 이상, OmniRoute까지 쓰면 8GB 이상 (Hermes 약 2.7GB, OmniRoute 0.8~1.9GB) |
| Discord | 본인 계정과 **본인이 소유한 서버** 하나 (없으면 새로 만들기) |
| 대화 모델 | ChatGPT 구독(로그인으로 연결) 또는 OpenCode Go·Command Code API 키 중 하나 |
| Gemini 키 | https://aistudio.google.com/apikey 에서 무료 키 발급 (영상 요약용, `AIza`로 시작) |
| 선택 | 음성(Groq), 차단 우회(Webshare), SNS 수집(Apify), Composio 앱 연동 키 — 당일 없어도 됨 |

같이 보낼 문장: "키와 토큰은 누구에게도 보내지 마세요. 강사도 받지 않습니다. 모델·API 요금과 VPS 요금은 각 서비스에서 따로 나옵니다."

강사는 기수 시작 전에 **현재 쓸 수 있는 대화 모델 ID**(예: ChatGPT 구독에서 실제 동작하는 ID)를 한 번 확인해 공지합니다. `/setup`은 정확한 모델 ID를 요구하고, 틀리면 연결 확인에서 실패합니다.

## 2. 설치 진행 (1인 약 40~60분)

### 2-1. Discord 봇 만들기 (10분)

1. https://discord.com/developers/applications → **New Application** → 이름 입력.
2. 왼쪽 **Bot** → **Reset Token** → 토큰 복사(한 번만 보임). 메모장에 잠깐 두고 공유하지 않게 합니다.
3. 같은 화면 **Privileged Gateway Intents**에서 **Message Content Intent**를 켜고 저장.

확인 지점: 토큰을 복사했고 Message Content Intent가 켜져 있다.

### 2-2. VPS에 배포 (10분)

1. Hostinger Docker Manager → 새 Compose 프로젝트 → [docker-compose.yml](../docker-compose.yml) 전체를 붙여넣기.
2. 환경변수 `DISCORD_BOT_TOKEN`에 토큰 입력(입력란이 자동으로 안 생기면 프로젝트 환경변수에서 직접 추가) → 배포.
3. 컨테이너 상태: `hermes`와 `syncthing`은 실행 중, `syncthing-init`은 **종료(0)가 정상**입니다(볼륨 권한만 맞추고 끝나는 컨테이너).

확인 지점: hermes 컨테이너 로그에 `[kit] 봇 초대:` 줄이 보인다.

### 2-3. 봇 초대 (5분)

1. 로그의 `[kit] 봇 초대:` 링크를 열어 **본인 서버**를 고르고 승인. 권한·인텐트 설정은 키트가 대신 합니다.
2. 서버 멤버 목록에 봇이 온라인으로 보이는지 확인.

확인 지점: 채팅창에 `/setup`, `/doctor`가 뜬다(처음엔 1~2분 걸릴 수 있음).

### 2-4. `/setup` (15~20분) — 반드시 서버 소유자 계정으로

1. **서비스 키 입력 · 변경** → Gemini 키 입력. 잘못된 키는 저장되지 않고 바로 알려 줍니다.
2. 대화 모델 연결:
   - ChatGPT 구독: **ChatGPT 로그인** → 봇이 보낸 링크를 열고 표시된 코드를 입력. "이 요청을 직접 시작한 경우에만 승인"하라고 짚어 줍니다.
   - API 제공자: **서비스 키 입력 · 변경**에서 해당 키 입력.
3. **두뇌 선택** → 제공자, 공지한 정확한 모델 ID, 용도 `main`. 보조 모델(`aux`)은 선택입니다. 지정하지 않으면 하위 작업도 대화 모델이 처리합니다.
4. **설치할 직무 스킬 선택** → 본인 직무(구직·세일즈·마케팅·기획·개발). 직무별 한국형 스킬도 같이 설치됩니다.
5. **연결 확인** → 성공하면 **적용하기 (재시작)**. 재시작 후 봇이 다시 온라인이 될 때까지 기다립니다.

확인 지점: 연결 확인이 "기본 키·선택 구성요소·모델 응답 확인 완료"로 끝났다.

### 2-5. 동작 확인 (5분)

1. `/doctor` → 빨간 항목이 없는지. **강사에게 보내기용 복사본**을 받아 기록해 둡니다.
2. 실제 질문 하나(예: "오늘 서울 날씨 알려줘" — 한국형 날씨 스킬 확인).
3. 짧은 공개 유튜브 영상 하나 요약(영상 요약 + Gemini 키 확인).

여기까지 되면 기본 설치 완료입니다.

## 3. 선택 기능 (필요한 학생만, 기본 설치가 끝난 뒤)

| 기능 | 순서 | 확인 |
|---|---|---|
| OMH | `/setup` → **OMH 설정** → 기본 팩 설치 → 적용하기(재시작) | "자료 세 개를 나눠서 조사해줘"처럼 위임이 필요한 요청 하나. 에이전트가 `omh_delegate_route`로 작업 종류를 정한 뒤 위임하는지 |
| Composio 앱 연동 | Composio Connect에서 `ck_` 키 발급 → **서비스 키 입력 · 변경** → Composio에서 쓸 앱(Gmail 등) 권한을 학생 본인이 허용 | "오늘 받은 메일 제목만 보여줘" 같은 읽기 요청 하나 |
| 일반 선톡 | **일반 선톡 켜기** → 주제·시각 | 테스트 채널에서만 켜고, 확인 후 필요 없으면 **선톡 끄기** |
| PC 노트 동기화 | [기기 연결 안내](student-sync-import.md) | PC와 서버 양쪽에 파일이 도착하는지 |
| OmniRoute | 8GB 이상 VPS에서만. [심화 Compose](../advanced/docker-compose.omniroute.yml)를 **두 번째 프로젝트**로 배포(`KIT_OMNIROUTE_PASSWORD`) → **OmniRoute 연결** | 연결 시 도구 왕복 검증이 통과하는지 |
| 백업 | 적용 시 주간 백업이 등록됨. **지금 백업**으로 한 번 실행 | 서버 밖 사본은 PC 동기화나 다운로드로 따로 확보 |

## 4. 원격 지원할 때

학생에게 받을 것:

- `/doctor` → **강사에게 보내기용 복사본** (마스킹된 텍스트)
- 막힌 화면의 스크린샷(키 입력란이 비어 있거나 가려진 상태)
- 필요하면 hermes 컨테이너 로그 마지막 50줄 (봇 토큰은 로그에 출력되지 않음)

받지 않을 것: 봇 토큰, API 키, `.env`, 대화 ZIP 원본, VPS root 비밀번호.

## 5. 증상별 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 로그에 `[kit] 봇 초대:`가 없고 "봇 토큰이 거부됐습니다" | 토큰 오타·만료 | Developer Portal에서 **Reset Token** → 환경변수 교체 → 재배포 |
| 봇은 온라인인데 일반 메시지에 반응 없음 | Message Content Intent 꺼짐 | Portal에서 켜고 저장 → 컨테이너 재시작 |
| `/setup`이 안 보임 | 명령 동기화 지연, 초대 누락 | 1~2분 대기 → Discord 새로고침 → 초대 링크로 다시 초대 |
| "이 서버의 소유자만 실행할 수 있습니다." | 소유자가 아닌 계정 | 서버 소유자 계정으로 실행(학생 본인 서버인지 확인) |
| "먼저 해당 제공자의 키를 입력해 주세요." | 두뇌 선택 전에 키가 없음 | **서비스 키 입력 · 변경**에서 키부터 |
| "모델 응답 확인에 실패했습니다. 로그인·모델 ID·사용 한도를 확인해 주세요." | 모델 ID 오타, 계정에 없는 모델, 한도 초과 | 공지한 모델 ID와 대조, ChatGPT는 로그인 다시, API는 잔액·한도 확인 |
| "두뇌 연결에서 제공자와 모델을 먼저 선택해 주세요." | 대화 모델 미지정 | **두뇌 선택**에서 용도 `main` 지정 |
| ChatGPT "로그인 대기 시간이 끝났습니다" | 코드 입력이 늦음 | **ChatGPT 로그인**을 다시 눌러 새 링크·코드로 |
| 직무 스킬·영상 요약 설치 실패 | 첫 부팅 때 네트워크 문제 | **설치 재시도** |
| "일부 설정 적용이 실패했다" | 적용 중 일부 실패 | 완료로 보지 말고 `/doctor` 복사본 확인 후 해당 단계 반복 |
| 컨테이너가 계속 재시작 | 메모리 부족(특히 OmniRoute 동시 실행) | VPS 사양 확인, OmniRoute 프로젝트를 먼저 중지 |

## 6. 업데이트 안내

새 버전을 공지할 때: Compose의 이미지 태그(`ghcr.io/wendy-nam/hermes-kit:0.21.2-kN`)만 바꿔 재배포하게 합니다.
데이터 볼륨은 유지되고 설정·키·노트는 그대로입니다. 공지 전에 해당 버전의 릴리스 노트(`docs/*-release.md`)에
학생이 따로 눌러야 할 것이 있는지 확인해 같이 알립니다. 실행 중인 컨테이너는 스스로 업데이트하지 않습니다.

## 7. 기수 시작 전 강사 리허설

README의 "강사·운영자 출시 기준"을 새 VPS·새 Discord 앱으로 한 번 끝까지 따라가고 소요 시간과 막힌 곳을
이 문서에 반영합니다. 강사 서버는 로컬 이미지(`hermes-agent:baseline-*`)로 돌아 공식 이미지와 소스가 다른 부분이
있으므로, 강사 서버에서 되는 것이 학생 이미지에서도 된다고 가정하지 않습니다.
