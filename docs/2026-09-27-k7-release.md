# hermes-kit 0.21.2-k7

k6은 태그 CI의 OMH 검사에서 막혀 게시되지 않았습니다. k6의 작업별 경로는
Hermes 0.21.2에 없는 `delegate_task(routing=...)`에 의존했기 때문입니다. 그대로
배포됐다면 강화 모드를 켠 학생의 위임이 모두 차단됐을 것입니다. k7은 이를
업스트림 OMH 자체 라우팅 위에서 다시 구현합니다.

**OMH**
- 기본 팩 설치 시 모든 작업 종류가 보조 모델로 위임됩니다. 작업 종류별 추론 강도는
  OMH 권장값(최대 high)을 따르고, OMH의 모델별 보정 문구가 함께 켜집니다. 보정은
  medium 이상 경로의 자식 작업에 붙으며, 실패해도 위임을 막지 않습니다.
- 작업별 모델과 대체 모델(최대 5개)을 저장할 수 있고, 저장은 작업별로 누적됩니다.
  `-`로 입력하면 그 작업만 기본값으로 되돌립니다. 대체 모델 전환은 OMH가 직접 처리합니다.
- **현재 경로·추천 보기**에서 설정과 OMH 추천 모델을 확인합니다.
- 보조 모델이나 OmniRoute 연결을 바꾸면 따로 지정하지 않은 작업도 따라갑니다.
- `/doctor`에 OMH 상태가 표시되고, 백업에 OMH 경로가 포함됩니다.

- OMH 기본 팩과 함께 워크플로우 스킬을 골라 설치합니다(결정, 리서치 브리프, 회의 브리프,
  산출물 패키지, 긴 문서 읽기, 실시간 정보, ULW 계획·인터뷰, 직무별 코드 리뷰·콘텐츠·데이터 분석).
  전체 124개는 매 턴 컨텍스트가 무거워 넣지 않습니다. `omh update` 후에도 유지됩니다.
- 모델이 바뀔 수 있는 콤보(패밀리 미상)에는 공통 하한 규칙을 항상 붙입니다. 보정 계산은
  게이트웨이 안에서 한 번 불러 캐시합니다.

**강사 서버에서 옮긴 수정**
- 칸반: 워커 크래시가 에이전트를 다시 깨우지 않고(재시도는 디스패처), 시작·진행 노트를 스레드에
  알리며(작업당 10분 1회), 실패 알림에 마지막 오류 줄(비밀값 가림)을 붙입니다. 워커는 진행 노트를
  남기도록 안내받습니다.
- 정책 훅(`pre_tool_call`)이 겹칠 때 건너뛰지 않고 기다립니다. OMH 거버넌스 훅에 해당합니다.
- 웹 추출 기본값을 키 없는 Parallel로 지정하고, 선택 설치 JS 페이지 추출기를 추가합니다.
- 새 설치의 SOUL에 위임·검증 규칙과 크론 단계 분할(회차당 1~2단계, JSON 체크포인트)을 넣습니다.

**한국형 스킬:** NomaDamas/k-skill(MIT)에서 고른 스킬 25개를 고정 커밋으로 포함합니다.
공통 6개는 모두에게, 나머지는 선택한 직무에 따라 설치됩니다. 실행 중 npm을
내려받지 않도록 원본 지침을 이미지 안의 스크립트 경로로 바꿔 두었습니다.

**OmniRoute 심화팩 (`omniroute-rtk-json-3`):** 업스트림 이미지에 압축 워커가 쓰는 패키지
8개(`xxhash-wasm`, `uuid` 등)가 빠져 있어, 워커가 뜨지 못하고 스트리밍 토큰마다 메인 스레드에서
압축하던 문제를 고쳤습니다. 잠금 파일로 고정한 버전만 추가합니다. 심화 Compose를 재배포해야
적용됩니다.

기존 학생은 데이터 볼륨을 유지하고 Hermes 태그를 `0.21.2-k7`로 재배포합니다.
OMH 기본 팩을 이미 설치한 학생은 **OMH 설정 → 보정 다시 켜기**를 누르면 권장
강도와 보정이 적용됩니다. 새 설치의 compact 스킬 목록·웹 추출 설정·SOUL만 바뀌며, 기존 학생의 설정과 SOUL은
바뀌지 않습니다.
