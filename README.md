# hermes-kit

수강생이 개인 VPS에 Hermes를 설치하고, Discord에서 모델·서비스 키·직무 스킬을 연결하는 키트입니다.
업무와 개인 노트는 별도 볼트로 관리합니다.

**현재 버전: `0.21.2-k16`** — 이미지 `ghcr.io/wendy-nam/hermes-kit:0.21.2-k16` (게시 완료되면 이 태그를 그대로 쓰면 됩니다).
이전 버전의 변경 사항은 [CHANGELOG](docs/CHANGELOG.md)에 있습니다. 강사용 설치 지원 절차는
[설치 도우미 안내](docs/instructor-install-guide.md)에 있습니다.
소스 저장소는 비공개이며 이미지 다운로드에는 GitHub 로그인이 필요하지 않습니다.

## 준비물

- Docker를 실행할 VPS (메모리 4GB 이상, 디스크 여유 6GB 이상)
  - 메모리가 7GB 미만이면 Compose가 스왑 2GB를 자동으로 만듭니다.
- 본인이 소유한 Discord 서버와 봇 토큰
- 사용할 모델 계정

기본 설정을 끝내려면 **대화 모델 하나**(ChatGPT 구독 로그인 또는 API 키 하나)와 **Gemini API 키**(무료 키, 영상 요약용)가 필요합니다. 나머지 서비스는 모두 선택 사항입니다. 모델·API 사용료와 VPS 요금은 각 서비스에서 따로 나옵니다.

## 수강생 설치 순서

1. Discord Developer Portal에서 새 앱과 봇을 만들고 봇 토큰을 발급합니다.
   - 왼쪽 **Bot** → **Reset Token**. **Privileged Gateway Intents**의 **Message Content Intent**를 켭니다.
2. [docker-compose.yml](docker-compose.yml)을 Hostinger Docker Manager의 Compose 프로젝트에 넣습니다.
   - 환경변수는 `DISCORD_BOT_TOKEN` 하나입니다. 환경변수 입력란이 자동 생성되지 않으면 프로젝트의 환경변수 설정에서 직접 추가합니다.
3. 배포 후 Hermes 컨테이너 로그의 `[kit] 봇 초대:` 링크를 열어 본인 서버에 초대합니다. 봇이 온라인으로 보이면 됩니다.
4. **서버 소유자 계정**으로 Discord에서 `/setup`을 실행하고, **설정 순서** 화면의 번호대로 누릅니다.
   1. **ChatGPT로 로그인** 또는 **API 키로 연결** — 권장 모델 ID가 미리 채워져 있고, 실제 응답을 확인한 뒤 저장합니다.
   2. **Gemini 키** — 영상 요약용 무료 키.
   3. **직무 선택** — 구직·세일즈·마케팅·기획·개발. 직무별 한국형 스킬도 같이 설치됩니다.
   4. **권장 설정 적용 (재시작)** — OMH와 역할 프로필(조사 `research`·코딩 `coder`·콘텐츠 `creator`)을 대화 모델로 설치하고, 연결 확인 후 재시작합니다.
5. 다시 연결된 뒤 `/doctor`와 실제 질문 하나로 확인합니다. 영상 요약도 짧은 공개 영상 하나로 시험해 보세요.

키트 상태는 `/setup → 고급 설정`의 **선택 기능 안내**에서 한눈에 볼 수 있습니다(기능 설명 + 현재 켜짐 여부). 키의 *값*은 절대 표시되지 않습니다.

비용을 최소화해야 한다면 [대화 모델 선택 가이드](docs/student-model-guide.md)를 보세요.

### 막혔을 때

| 상황 | 할 일 |
|---|---|
| 초대 링크가 로그에 안 보임 | 이미 초대했다면 Discord에서 **`/invite`**. 아직 초대 전이라면 `/invite` 가 Developer Portal의 URL Generator 절차를 안내합니다. VPS 접근이 가능하면 `docker compose exec hermes /opt/hermes/.venv/bin/python /opt/data/plugins/kit-setup/owner.py` 로도 같은 링크가 나옵니다. |
| 봇은 온라인인데 메시지에 반응 없음 | Portal에서 **Message Content Intent**를 켜고 저장 → 컨테이너 재시작 |
| `/setup`이 안 보임 | 1~2분 대기 → Discord 새로고침 → 초대 링크로 다시 초대 |
| 이 서버의 소유자만 실행할 수 있습니다 | `/setup`을 연 사람이 서버 소유자가 아닙니다. 본인 서버 소유자 계정으로 실행하세요 |
| 모델 응답 확인 실패 | 모델 ID 오타, 계정에 없는 모델, 사용 한도 초과. 다시 로그인하거나 키의 잔액·한도를 확인 |
| 설치 중 일부 실패 | 완료로 보지 말고 **설치 재시도** 또는 해당 단계를 다시 실행한 뒤 `/doctor` 확인 |
| 컨테이너가 재시작을 반복 | 메모리 부족. `swap-init` 로그를 보고, 스왑이 안 잡혔으면 VPS에서 스왑을 직접 만듭니다. 심화 프로젝트(OmniRoute)를 먼저 중지해 보세요 |

`/doctor`의 **강사에게 보내기용 복사본**은 키·토큰이 마스킹된 텍스트입니다. 그 복사본과 스크린샷은 괜찮지만, **API 키·봇 토큰·대화 ZIP 원본은 누구에게도 보내지 마세요.**

## 키 목록

Compose 환경변수는 `DISCORD_BOT_TOKEN` 하나입니다. 나머지 키는 입력 즉시 검증되도록 모두 `/setup`의 설정 순서 또는 **고급 설정 → 서비스 키 입력 · 변경**에서 받습니다. 잘못된 키는 저장되지 않습니다.

| `/setup` 항목 | 키 | 필요 여부 |
|---|---|---|
| 기본 (영상 요약) | `GEMINI_API_KEY` (무료 키 가능) | 필수 |
| 대화 모델 | ChatGPT 구독은 **ChatGPT 로그인**, API 제공자는 아래 해당 키 | 필수 (하나). 비용 최소 선택지는 [대화 모델 가이드](student-model-guide.md) |
| 보조 모델: OpenCode Go | `OPENCODE_GO_API_KEY` | 선택. 위임을 따로 돌릴 때만 |
| 보조 모델: Command Code | `COMMANDCODE_API_KEY` | 선택. 위임을 따로 돌릴 때만 |
| 음성 비서 (한국어) | `GROQ_API_KEY` | 선택 |
| 차단 우회 (원티드 등) | `WEBSHARE_PROXY_USERNAME`, `WEBSHARE_PROXY_PASSWORD` | 선택 |
| SNS·플랫폼 수집 | `APIFY_TOKEN` | 선택 |
| Composio 앱 연동 (MCP) | `COMPOSIO_CONSUMER_KEY` (`ck_`로 시작) | 선택. 앱 권한 허용은 Composio에서 본인이 |
| OmniRoute 연결 | 대시보드 비밀번호·제공자 키 (**OmniRoute 연결** 메뉴) | 선택. 심화 Compose 배포 후 |

보조 모델을 지정하지 않으면 하위 작업(위임)도 대화 모델이 처리합니다. 지정하는 이유는 위임을 더 싼 모델·다른 모델로 돌리기 위해서뿐입니다.

## 선택 기능

모두 **기본 설치가 끝난 뒤** `/setup → 고급 설정`에서 켭니다.

- **한국형 스킬 (k-skill):** [NomaDamas/k-skill](https://github.com/NomaDamas/k-skill)(MIT)에서 키 없이 쓰는 스킬을 골라 고정 커밋으로 이미지에 넣었습니다. 모든 학생에게 날씨·미세먼지·네이버 뉴스·긱뉴스·공휴일·맞춤법 검사가 설치되고, 직무별로 구직·세일즈·마케팅·기획·개발 스킬이 추가됩니다. 대부분 제작자의 공개 프록시를 거치므로 검색어가 그 서버에 전달됩니다([개인정보 처리방침](https://k-skill-proxy.nomadamas.org/privacy)). 목록은 [kskills.json](plugins/kit-setup/kskills.json).
- **PC 노트 동기화·대화 가져오기:** [기기 연결과 ChatGPT·Claude ZIP 가져오기](docs/student-sync-import.md)를 따릅니다. 서버 설정 저장만으로 PC 연결이 끝나지는 않습니다. PC에서 장치와 폴더를 수락하고 **양방향 파일 도착까지** 확인하세요. 가져온 대화는 노트로 저장되며 자동 기억 등록은 하지 않습니다.
- **OMH·역할 프로필:** 설정 순서 4단계에서 설치됩니다. 이번 답변 안에 끝나는 병렬 하위 작업은 OMH로 위임하고, 오래 걸리거나 여러 단계인 일은 kanban 카드로 만들어 역할 프로필에 맡깁니다. 역할 프로필은 봇 토큰 없이 백그라운드에서만 돌고, 적용할 때마다 기본 봇의 키와 모델 설정을 받습니다. 7GB 미만 VPS에서는 한 번에 하나만 돕습니다. `omh update`를 실행하면 경로 요청과 보정이 꺼지므로 키트가 설치한 OMH는 업데이트하지 마세요.
- **이미지 읽기:** OmniRoute 모델을 연결한 뒤 `/setup`의 **이미지 연결**에서 합성 이미지 시험을 통과한 모델만 등록합니다. 기본 대화 모델은 그대로 유지되며, 이미 다른 이미지 모델이 설정돼 있으면 자동 교체하지 않습니다.
- **JS 페이지 추출기:** 기본 웹 읽기가 스크립트 페이지에서 빈 결과를 줄 때만 로컬 브라우저로 다시 읽습니다. 디스크 약 1GB를 쓰고 내부망 주소는 읽지 않습니다. 같은 화면에서 제거할 수 있습니다.
- **일반 선톡:** 주제와 시각을 정하면 그 채널에 하루 한 번 짧은 글을 보냅니다. 처음에는 꺼져 있으며 **선톡 끄기**로 해제합니다. 처음에는 테스트 채널에서만 켜세요.
- **OmniRoute:** 필요할 때만 [심화 Compose](advanced/docker-compose.omniroute.yml)를 **두 번째 프로젝트**로 배포합니다(`KIT_OMNIROUTE_PASSWORD` — 비우면 Compose가 거부하고 기동을 멈춥니다. 4GB VPS 가능, 메모리 2GB 상한). **반드시 기본 프로젝트를 먼저 배포하세요.** 심화 프로젝트는 기본 프로젝트의 네트워크를 공유하므로, 나중에 기본 프로젝트를 `docker compose down`으로 지우면 대시보드가 끊깁니다. `/setup → 고급 설정 → OmniRoute 연결`에서 **1. 대시보드 열기(15분 링크, SSH 불필요)** → 대시보드에서 계정 연결 → **2. 모델 고르기(목록)** → **3. `고급 설정`의 `적용하기 (재시작)`** 순서로 진행합니다. 이 마지막 재시작을 빠뜨리면 연결은 되어도 대화가 그대로입니다. 사용을 마치면 **대시보드 링크 닫기**를 누르세요(15분 뒤 자동 종료). **API 키 하나로 연결**은 보조(위임) 모델만 OmniRoute에 둡니다. **OmniRoute 모드**는 대시보드에서 직접 연결한 계정의 모델을 대화용·강한 작업용으로 최대 5개씩 받아 하나의 콤보로 묶습니다. 지금 쓰던 직접 연결 모델이 대체 경로로 남아 OmniRoute가 멈춰도 봇이 답합니다. **모드 끄기**로 되돌립니다. 업데이트·복구 방법은 [OmniRoute 업데이트](docs/ops/omniroute-updates.md)를 참고하세요.
- **백업·연결 해제:** 적용 시 주간 백업·업데이트 확인을 등록합니다. **지금 백업**으로 수동 백업도 가능합니다. 연결 해제는 서비스 키와 키트가 변경한 설정을 대상으로 하며, OAuth와 외부 앱 권한은 해당 서비스에서 별도로 해제합니다.

백업이 같은 VPS에만 있으면 서버 삭제 시 함께 사라집니다. PC 동기화 또는 다운로드로 서버 밖 사본을 확보하세요. 백업에는 인증정보와 대화 세션 DB가 포함되지 않으며, 복구 후 키·로그인은 다시 연결해야 합니다. [백업·복구 절차](docs/ops/recovery.md)를 참고하세요.
