# hermes-kit

수강생이 개인 VPS에 Hermes를 설치하고 Discord에서 모델·서비스 키·직무 스킬을 연결하는 키트입니다. 업무와 개인 노트는 별도 볼트로 관리합니다.

**현재 상태: `0.21.2-k14` 준비 중.** k14는 OmniRoute 대시보드를 SSH 없이 15분 링크로 열고, 모델을 목록에서 고르게 합니다([k14 안내](docs/2026-09-28-k14-release.md)). k13은 4GB VPS 보호(스왑·작업 동시 실행 제한)와 OmniRoute 모드를 추가합니다([k13 안내](docs/2026-09-28-k13-release.md)). k4~k10은 `/setup`·`/doctor`가 Discord에 등록되지 않아 k11 이상으로 재배포해야 합니다([k11 안내](docs/2026-09-28-k11-release.md)). k12는 `/setup`을 4단계 설정 순서로 바꾸고 역할 프로필을 추가합니다([k12 안내](docs/2026-09-28-k12-release.md)). 강사용 설치 지원 절차는 [설치 도우미 안내](docs/instructor-install-guide.md)에 있습니다. 소스 저장소는 비공개이며 이미지 다운로드에는 GitHub 로그인이 필요하지 않습니다.

## 수강생 설치 순서

준비물은 Docker를 실행할 VPS(메모리 4GB 이상; 7GB 미만이면 Compose가 스왑 2GB를 자동으로 만듭니다), 본인이 소유한 Discord 서버와 봇 토큰, 사용할 모델 계정입니다. 현재 기본 설정 완료에는 Gemini API 키(영상 요약)와 정상 응답하는 대화 모델 하나가 필요합니다. 보조 모델은 선택입니다. 지정하지 않으면 하위 작업도 대화 모델이 처리하고, 위임을 싼 모델로 돌리고 싶을 때만 OpenCode Go·Command Code·OmniRoute 등을 추가합니다. 모델·API 사용료와 VPS 요금은 각 서비스에서 별도로 발생합니다.

1. Discord Developer Portal에서 새 앱과 봇을 만들고 봇 토큰을 발급합니다.
2. [docker-compose.yml](docker-compose.yml)을 Hostinger Docker Manager의 Compose 프로젝트에 넣습니다. 환경변수는 아래 표대로 입력합니다. 환경변수 입력란이 자동 생성되지 않으면 프로젝트의 환경변수 설정에서 직접 추가합니다.
3. 배포 후 Hermes 컨테이너 로그의 `[kit] 봇 초대:` 링크를 열어 본인 서버에 초대합니다. 링크가 없거나 Discord가 인텐트 오류를 표시하면 로그를 확인하고 Developer Portal의 Message Content Intent 설정을 점검합니다. 토큰 자체를 채팅에 보내지 마세요.
4. 서버 소유자 계정으로 Discord에서 `/setup`을 실행합니다. **설정 순서** 화면의 번호대로 누릅니다.
   1. **ChatGPT로 로그인** 또는 **API 키로 연결** — 권장 모델 ID가 미리 채워져 있고, 실제 응답을 확인한 뒤 저장합니다.
   2. **Gemini 키** — 영상 요약용 무료 키.
   3. **직무 선택** — 구직·세일즈·마케팅·기획·개발. 직무별 한국형 스킬도 같이 설치됩니다.
   4. **권장 설정 적용 (재시작)** — OMH와 역할 프로필(조사 `research`·코딩 `coder`·콘텐츠 `creator`)을 대화 모델로 설치하고, 연결 확인 후 재시작합니다.
5. 다시 연결된 뒤 `/doctor`와 실제 질문 하나로 확인합니다. 영상 요약도 짧은 공개 영상 하나로 시험해 보세요. PC 옵시디언에서 노트를 보려면 **PC 옵시디언에서 노트 보기**를 따릅니다. 나머지 기능은 **고급 설정**에 있습니다.

**역할 프로필:** 기본 봇이 대화와 지휘를 맡습니다. 이번 답변 안에 끝나는 병렬 하위 작업은 OMH로 위임하고, 오래 걸리거나 여러 단계인 일은 kanban 카드로 만들어 역할 프로필에 맡깁니다. 역할 프로필은 봇 토큰 없이 백그라운드에서만 돌고, 적용할 때마다 기본 봇의 키와 모델 설정을 받습니다. 보조 모델(또는 OmniRoute 모드의 강한 작업 콤보)이 있으면 그 모델로, 없으면 대화 모델로 돕니다. 7GB 미만 VPS에서는 한 번에 하나만 돕니다. 역할 프로필의 `SOUL.md`를 직접 고치면 그 뒤로는 덮어쓰지 않습니다.

Compose 환경변수는 `DISCORD_BOT_TOKEN`(본인이 만든 Discord 봇 토큰) 하나입니다. 나머지 키는 입력 즉시 검증되도록 모두 `/setup`의 설정 순서 또는 **고급 설정 → 서비스 키 입력 · 변경**에서 받습니다.

| `/setup` 항목 | 키 | 필요 여부 |
|---|---|---|
| 기본 (영상 요약) | `GEMINI_API_KEY` (무료 키 가능) | 필수 |
| 대화 모델 | ChatGPT 구독은 **ChatGPT 로그인**, API 제공자는 아래 해당 키 | 필수 (하나) |
| 보조 모델: OpenCode Go | `OPENCODE_GO_API_KEY` | 선택. 위임을 따로 돌릴 때만 |
| 보조 모델: Command Code | `COMMANDCODE_API_KEY` | 선택. 위임을 따로 돌릴 때만 |
| 음성 비서 (한국어) | `GROQ_API_KEY` | 선택 |
| 차단 우회 (원티드 등) | `WEBSHARE_PROXY_USERNAME`, `WEBSHARE_PROXY_PASSWORD` | 선택 |
| SNS·플랫폼 수집 | `APIFY_TOKEN` | 선택 |
| Composio 앱 연동 (MCP) | `COMPOSIO_CONSUMER_KEY` (`ck_`로 시작) | 선택. 앱 권한 허용은 Composio에서 본인이 |
| OmniRoute 연결 | 대시보드 비밀번호·제공자 키 (**OmniRoute 연결** 메뉴) | 선택. 심화 Compose 배포 후 |

키 검증 실패 시 해당 입력은 저장하지 않습니다. 일부 설정 적용이 실패했다는 안내가 나오면 완료로 보지 말고 다시 확인하세요. 초기 스킬 설치가 네트워크 문제로 실패하면 **설치 재시도**를 사용할 수 있습니다. `/doctor`의 복사본을 강사에게 전달하되, API 키·봇 토큰·대화 ZIP 원본은 보내지 마세요.

## 선택 기능

- **한국형 스킬 (k-skill):** [NomaDamas/k-skill](https://github.com/NomaDamas/k-skill)(MIT)에서 키 없이 쓰는 스킬을 골라 고정 커밋으로 이미지에 넣었습니다. 모든 학생에게 날씨·미세먼지·네이버 뉴스·긱뉴스·공휴일·맞춤법 검사가 설치됩니다. 직무별로는 구직(공고 적합도·당근 알바·국민연금 사업장·기업 실사·자소서 다듬기), 세일즈(기업 실사·나라장터 발주계획·정부지원 전수조사·인허가 영업상태), 마케팅(네이버 쇼핑·블로그 조사·다나와 가격·글 다듬기·장수 점포 상권), 기획(정부지원·K-Startup·법령 검색), 개발(도메인 WHOIS)이 추가됩니다. 대부분 k-skill 제작자의 공개 프록시(`k-skill-proxy.nomadamas.org`)를 거치므로 검색어가 그 서버에 전달됩니다([개인정보 처리방침](https://k-skill-proxy.nomadamas.org/privacy)). 실행 중에 npm 코드를 내려받지 않습니다. 목록은 [kskills.json](plugins/kit-setup/kskills.json), 갱신은 `scripts/vendor-kskill.py`로 합니다.
- **카카오톡 옵션팩 (설계본):** [스킬](optional-packs/kakaotalk/SKILL.md)과 [하네스 설계](optional-packs/kakaotalk/references/harness.md)를 별도로 관리합니다. 기본 이미지·자동 설치에 포함되지 않으며, 연결 프로그램과 설정 UI는 아직 구현되지 않았습니다. Teams는 이 옵션팩 범위에서 제외합니다.

- **PC 동기화·대화 가져오기:** [기기 연결과 ChatGPT·Claude ZIP 가져오기](docs/student-sync-import.md)를 따릅니다. 서버 설정 저장만으로 PC 연결이 끝나지는 않습니다. PC에서 장치와 폴더를 수락하고 양방향 파일 도착까지 확인하세요. 가져온 대화는 노트로 저장되며 자동 기억 등록은 하지 않습니다.
- **일반 선톡:** `/setup`의 **일반 선톡 켜기**에서 주제와 시각을 정하면 그 설정 화면을 연 채널에 하루 한 번 짧은 글을 보냅니다. 처음에는 꺼져 있으며 **선톡 끄기**로 해제합니다. 생성 작업은 도구·기억·개인 상태를 읽지 않는 격리 워커를 사용합니다. 자아 플러그인과 셀카 선톡은 학생 키트에 포함하지 않습니다.
- **OMH:** 설정 순서 4단계에서 설치됩니다(고급 설정의 **OMH 설정 → 기본 팩 설치**도 같은 설치). 고정한 upstream 핵심 워크플로우를 설치하며 memory mode는 꺼집니다. 모든 작업 종류가 보조 모델(지정하지 않았으면 대화 모델)로 위임되고, 결정·리서치 브리프·회의 브리프·산출물 정리·긴 문서 읽기·ULW 계획/인터뷰 워크플로우 스킬(직무에 따라 코드 리뷰·콘텐츠·데이터 분석 추가)이 함께 설치되며, 작업 종류별 OMH 권장 추론 강도(고난도·깊은 분석·설계 등은 high, 간단한 작업은 low)와 모델별 보정 문구가 함께 켜집니다. 에이전트가 위임 전에 `omh_delegate_route`로 작업 종류를 정해야 이 경로·강도·보정이 적용되므로, 정하지 않은 위임은 한 턴에 한 번 되돌려 먼저 정하게 합니다(다시 시도하면 보조 모델 기본값으로 진행). 보정은 medium 이상에서 붙고, 모델이 바뀔 수 있는 콤보에는 검증·부분 수정·근거 없는 완료 금지 규칙이 항상 붙습니다. 작업을 골라 그 작업만 다른 모델과 대체 모델(최대 5개)을 지정할 수 있고, 저장은 작업별로 누적됩니다. **현재 경로·추천 보기**에서 설정과 OMH 추천 모델을 확인하고, 보조 모델(없으면 대화 모델)을 바꾸면 따로 지정하지 않은 작업도 따라갑니다. `omh update`를 실행하면 경로 요청과 보정이 꺼지므로 키트가 설치한 OMH는 업데이트하지 마세요. 강사의 개인 체인·자아 설정·커스텀 패치는 복사하지 않습니다. 재시작 후 간단한 실제 위임까지 확인해야 사용 준비가 끝납니다.
- **이미지 읽기:** OmniRoute 모델을 연결한 뒤 `/setup`의 **이미지 연결**에서 합성 이미지 시험을 통과한 모델만 등록합니다. 공유 Vision Bridge를 끄는 선택은 같은 OmniRoute를 쓰는 다른 앱에도 영향을 줍니다. 기본 대화 모델은 그대로 유지하며, 이미 다른 이미지 모델이 설정돼 있으면 자동 교체하지 않습니다. 이미지 연결 후 보조 모델을 바꾸려면 같은 화면에서 `disconnect`를 선택해 이미지 연결을 먼저 해제해야 합니다. 해제에는 비밀번호가 필요 없고, 키트가 바꾼 이미지 설정만 복원합니다. 자동 첨부 분석은 최대 두 개 병렬·전체 30초 제한이며 실패한 이미지를 같은 턴에서 재시도하도록 유도하지 않습니다.
- **JS 페이지 추출기:** `/setup → 고급 설정 → 추가 기능`에서 설치합니다. 기본 웹 읽기(키 없는 Parallel)가 스크립트로 그려지는 페이지에서 빈 결과를 줄 때만 로컬 브라우저로 다시 읽습니다. 디스크 약 1GB를 쓰며, 이미지에 있는 브라우저를 재사용하므로 따로 내려받지 않습니다. 내부망 주소는 읽지 않습니다. 같은 화면에서 제거할 수 있습니다.
- **OmniRoute:** 필요할 때만 [심화 Compose](advanced/docker-compose.omniroute.yml)를 별도 프로젝트로 배포합니다(`KIT_OMNIROUTE_PASSWORD`, 4GB VPS 가능 — 메모리 2GB 상한). `/setup → 고급 설정 → OmniRoute 연결`에서 **1. 대시보드 열기(15분 링크, SSH 불필요)** → 대시보드에서 계정 연결 → **2. 모델 고르기(목록)** 순서로 진행합니다. 방식은 둘 중 하나입니다. **API 키 하나로 연결**은 보조(위임) 모델만 OmniRoute에 둡니다. **OmniRoute 모드**는 대시보드에서 직접 연결한 계정의 모델 ID(`접두사/모델`)를 대화용·강한 작업용으로 최대 5개씩 받아, 하나씩 도구 호출 시험을 한 뒤 통과한 것만으로 콤보를 만듭니다. 대화는 대화용 콤보, 위임·OMH·역할 프로필은 강한 작업용 콤보로 가고, 지금 쓰던 직접 연결 모델이 대체 경로로 남아 OmniRoute가 멈춰도 봇이 답합니다. 웹 스크래핑 제공자는 쓰지 않습니다. **모드 끄기**로 되돌립니다. 기본 이미지는 `next-web` 기반에 [Hermes JSON RTK 어댑터](advanced/omniroute-rtk-envelope/README.md)를 포함하며, 대화 모델이 OmniRoute를 거치면 Hermes RTK는 자동으로 꺼집니다. 업데이트·복구 방법은 [OmniRoute 업데이트](docs/ops/omniroute-updates.md)를 참고하세요.
- **백업·연결 해제:** 적용 시 주간 백업·업데이트 확인을 등록합니다. **지금 백업**으로 수동 백업도 가능합니다. 연결 해제는 서비스 키와 키트가 변경한 설정을 대상으로 하며, OAuth와 외부 앱 권한은 해당 서비스에서 별도로 해제합니다.

백업이 같은 VPS에만 있으면 서버 삭제 시 함께 사라집니다. PC 동기화 또는 다운로드로 서버 밖 사본을 확보하세요. 백업에는 인증정보와 대화 세션 DB가 포함되지 않으며, 복구 후 키·로그인은 다시 연결해야 합니다. [백업·복구 절차](docs/ops/recovery.md)를 참고하세요.

## 강사·운영자 출시 기준

현재 검증은 격리된 이미지·가짜 상위 API·단위 테스트를 포함합니다. **학생의 실제 OAuth 로그인, 유료 계정 권한, Discord 전체 설정 완료, 실제 PC 동기화 성공을 입증하는 결과는 아닙니다.** OMH 설치 점검과 실제 학생 작업의 위임 성공도 구분합니다. 구현·검증 범위는 [구성요소 계약](plugins/kit-setup/COMPONENTS.md)에 기록되어 있습니다.

기수에 배포하기 전에 다음을 완료합니다.

1. 새 VPS·새 Discord 앱으로 이 문서만 따라 설치하고 소요 시간을 기록합니다. 기본 대화, 보조 위임, 영상 요약, 선택 서비스의 실제 응답을 확인합니다.
2. 키 오류·모델 ID 오류·네트워크 단절 후 재시도, 재부팅, 일반 선톡 켜기와 끄기를 확인합니다. 선톡 검증은 테스트 채널에서 명시적으로 선택한 경우에만 진행합니다.
3. 실제 PC에서 양방향 동기화를 확인하고 샘플 대화 ZIP을 가져옵니다. 백업을 새 디렉터리에 복구해 노트와 중지된 크론을 확인합니다.
4. `versions.env`, Compose 이미지 태그, 릴리스 안내를 맞춥니다. 공개 게시를 결정한 뒤 버전 태그를 푸시합니다. 현재 CI는 `v*` 태그에서 모든 검증을 통과해야 GHCR에 게시하며, 일반 브랜치 푸시는 이미지를 게시하지 않습니다. 태그를 푸시할 수 없는 환경에서는 Actions의 `build`를 main에서 수동 실행하고 `release`에 `versions.env`와 같은 버전(예: `0.21.2-k7`)을 입력합니다. 같은 검증을 통과한 뒤 게시하고 `v*` 태그를 기록합니다.
5. GitHub 패키지의 공개 접근을 확인하고, 로그인하지 않은 새 환경에서 정확한 버전 이미지를 내려받아 부팅합니다. 이전 이미지와 데이터 백업을 보존한 뒤 수강생에게 게시 완료를 안내합니다.

개발 검증은 다음과 같이 실행합니다. Docker 이미지 빌드와 부팅 시험은 Docker가 실행 중인 환경에서 수행합니다.

```sh
python3 -m pip install pyyaml
python3 -m unittest discover -s tests -v
python3 -m unittest discover -s plugins/kit-setup/tests -v
set -a
. ./versions.env
set +a
docker build --build-arg HERMES_BASE_IMAGE --build-arg HERMES_VERSION \
  --build-arg RTK_VERSION --build-arg KIT_VERSION -t hermes-kit:check .
sh scripts/secret-scan.sh hermes-kit:check
sh scripts/boot-test.sh hermes-kit:check
```

이 저장소의 `ops/`는 강사 운영 환경의 감사·이전 기록입니다. 학생 서버에 통째로 실행하는 설치 단계가 아닙니다. 학생 설치의 시작점은 Compose와 `/setup`입니다.
